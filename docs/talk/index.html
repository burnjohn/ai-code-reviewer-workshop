Tier 1 — high impact, directly visible
T1-1Hard-coded secrets committed

2 live keys sit as string literals in a committed source file, and the CSV export signs its responses with one of them. Everyone with read access to the repo holds the signing key, and rotating it takes a code change and a deploy. Config belongs in .env only.

AC-10.1configs/analytics.js:2
analyticsController.js:564
T1-2Client imports server signing secret

The export button reaches across the package boundary — import … from '../../../../../server/src/configs/analytics.js' — so Vite inlines the HMAC key into the browser bundle, where any visitor can read it. The spec forbids both halves: no committed secrets, and client code never imports from server/.

AC-10.1analytics/ExportButton.jsx:5
T1-3Bearer token written to logs

console.log('[analytics] auth header:', req.headers.authorization) copies the caller's whole Authorization header into stdout on every view. Log storage is not a secret store, and a JWT read out of it is replayable until it expires.

AC-10.2analyticsController.js:708
T1-4Stored XSS in recent comments

The comment excerpt is injected with dangerouslySetInnerHTML. Comment text comes from anonymous visitors, so a script in a comment executes inside the admin's session, with the admin's token in hand. The spec asks for a plain-text excerpt with HTML stripped, never rendered.

AC-4.3tables/RecentCommentsTable.jsx:48
T1-5Visitor identity taken from request body

visitorKey and referrerSource are read from req.body, so the caller decides who they are: a fresh random key on each request walks straight past the 24-hour deduplication, and the traffic-source breakdown is whatever the caller types. Both must be derived on the server — sha256(ip + user-agent) and the Referer header.

AC-6.3analyticsController.js:655
Tier 2 — contract, lifecycle, data safety
T2-1Analytics routes never check admin role

adminRouter.use(auth) is the only gate, and auth.js verifies the signature, sets req.user and calls next() — it never looks at role. Any valid token, whatever role it carries, reads every analytics endpoint. The spec requires a valid JWT and role === 'admin', with 403 for anyone else.

AC-1.2routes/adminRoutes.js:21
middleware/auth.js:16
T2-2The correct implementation exists, unused

viewTracking.js already does exactly what the spec asks: server-side visitor key, referrer classified from the Referer header, 24-hour dedup that silently skips. Nothing imports it. The controller re-implements the same 3 rules and gets all 3 wrong (T1-5, T2-11, T2-12). 2 implementations, the working one dead, is worse than 1 — the next developer will fix the wrong copy.

AC-6.3 AC-6.4utils/viewTracking.js:78
T2-3Global rate limit raised 100 → 300

apiLimiter.max went from 100 to 300 for the entire API, with the comment "analytics dashboard uses ~9 parallel requests per interaction". So one page's chattiness triples the ceiling on login, comments and every public route, and the per-endpoint limit of 30/min the spec asks for on /view was never added. Global limits are also listed as out of scope for this PR.

AC-6.7 §11middleware/rateLimiter.js:42
T2-4CSV formula injection not neutralized

escapeCSV quotes commas, quotes and newlines — and stops there. A post titled =HYPERLINK("http://evil","Invoice") lands in the file as a formula, and Excel or Sheets evaluates it the moment an admin opens the export. Any cell starting with =, +, - or @ must be prefixed with a single quote.

AC-5.6analyticsController.js:577
T2-5Custom range to excludes the last day

parseDate turns 2026-02-11 into 2026-02-11T00:00:00.000Z and uses it as the upper bound, so the range stops at midnight and the entire last day of every custom range is silently dropped. The numbers look plausible, which is what makes it dangerous. The spec makes to inclusive.

AC-5.4validators/analyticsValidator.js:13
T2-6Categories sorted ascending, contract says descending

The aggregation ends with $sort: { views: 1 }, so the API hands back the least-viewed category first, and the client is explicitly told not to re-sort. The "Views by category" bar chart therefore reads upside down: the weakest category sits at the top where a reader expects the strongest.

AC-3.5analyticsController.js:343
T2-7category missing from query dependencies

useAnalyticsKpis sends category in the request but lists only [period, from, to] as dependencies, so changing the category never triggers a re-fetch. The charts below update, the KPI cards keep the previous category's numbers, and the page shows 2 different filters at once with nothing to indicate it. Every section must re-fetch on a filter change.

AC-5.3queries/useAnalytics.js:13
T2-830-second polling with no cleanup

useEffect(() => { setInterval(refetch, 30000) }, [refetch]) returns no cleanup function, so every remount leaves the previous timer alive: navigate in and out 5 times and the dashboard fires 5 overlapping refetches forever, against a stale refetch closure. Beyond the leak, background polling is ruled out entirely — data loads on page open and on filter change.

AC-10.5analytics/KpiSection.jsx:18
T2-9Migration rollback drops the collection

The migration's up creates 2 indexes; its down calls db.collection('blogviews').drop(). A routine rollback — the thing you reach for when a deploy goes wrong — therefore deletes every view ever recorded, and the log line still says "Indexes removed successfully". down must restore the previous schema without deleting data; here it should drop the 2 indexes by name.

AC-10.3migrations/…-add-blogview-indexes.js:39
T2-10Whole process.env serialized into the bundle

define: { 'process.env': JSON.stringify(process.env) } replaces every process.env in client code with the build machine's entire environment — database URL, JWT_SECRET, CI tokens. Today no client file reads process.env, so nothing leaks yet: it is a loaded gun, and the first process.env.X anyone adds ships every secret to every visitor. (Our original label said “leaks now” — one reviewer correctly pushed back.)

AC-10.1client/vite.config.js:13
T2-11Duplicate view returns 400 instead of 200

When the 24-hour dedup check finds an existing view, the endpoint answers 400 VIEW_ALREADY_RECORDED. But a repeat visit is the normal case, not a client error: the browser console fills with red, error monitoring counts it as a failure, and any retry logic treats it as something to retry. Deduplication should answer 200 without creating a document and never surface as an error.

AC-6.5analyticsController.js:693
T2-12Author's own views counted as public

Only decoded?.role === 'admin' sets isAdminView. An author re-reading and re-checking their own post is stored as an ordinary public view, so the person with the most reason to open a post is the one inflating its numbers — and the metric quietly rewards refreshing. The spec marks views from role admin or author as internal and excludes them from every statistic.

AC-6.6analyticsController.js:710
Tier 3 — subtle scope, performance, locale, tests
T3-1Client never sends the POST /view it declares

RECORD_VIEW is defined in the endpoints file and never called: BlogDetail.jsx opens a post without telling the server. Endpoint, model, indexes and dedup all exist and all sit idle, so every views figure on the dashboard comes from seeded fixtures — the feature demos perfectly and measures nothing in production. There is no wrong line to point at; the defect is the call that isn't there.

AC-6.1constants/apiEndpoints.js:33
public/BlogDetail.jsx — no call
T3-2N+1 queries in CSV export

exportCsv loads every matching post, then runs 2 countDocuments calls per post inside a sequential for loop — 500 posts means 1 001 round trips, awaited one after another. The export is fine on seed data and dies as the blog grows. Each endpoint must issue a bounded number of queries regardless of post count.

AC-10.4analyticsController.js:540
T3-3Unvalidated regex search, and out of scope

2 defects in 1 line. ?search= is passed into { $regex: req.query.search } unescaped, so a caller controls the pattern and can hand the database one that backtracks catastrophically. The deeper problem is that free-text search of posts is listed under Out of scope for this PR — the code shouldn't exist here at all, which is why finding only the ReDoS half scores a partial hit.

§11analyticsController.js:360
T3-4Dates follow the browser locale, not en-US

formatShortDate calls toLocaleDateString(undefined, …), and undefined means "whatever locale this browser has". The same dashboard reads Feb 11, 2026 for one admin and 11 февр. 2026 г. for another, next to numbers that are pinned to en-US 3 functions above. The spec fixes both to en-US regardless of browser.

AC-1.3utils/formatters.js:33
T3-5Tests assert nothing; 2 are skipped

The single live case ends in expect(container).toBeTruthy() — true even if the card renders an empty div — and the 2 cases that encode the real rules, the trend arrow and the hidden trend for all-time, are it.skip with empty bodies. The suite is green, the file counts toward coverage, and nothing named in the spec is actually verified.

AC-9.1analytics/KpiCard.test.jsx:9
T3-6Stale drill-down response overwrites the current one

handleDrillDown awaits the request and writes the result into state without checking whether it is still wanted. Click 5 Feb, then 6 Feb before the first reply lands, and the slower response for 5 Feb arrives last and fills the modal — the title says one date, the rows are another. The fix is an AbortController or a request-id guard; the spec requires the earlier response to be discarded.

AC-3.7admin/Analytics.jsx:60
T3-7All-time period still renders a trend

For period=all the range starts at new Date(0), and getPreviousPeriod just subtracts the range length — so the "previous period" is 1914 to 1970. It contains nothing, calculateTrend hits its previous === 0 branch, and every KPI card proudly shows +100%. For an all-time view the trend must be hidden: there is no earlier period to compare against.

AC-2.7helpers/analyticsAggregations.js:28
T3-9Tests added for unrelated components

The PR adds 12 test files for Navbar, Footer, SocialShare, CommentList, the blog generator hook — and 1 near-empty test for analytics. Coverage goes up, the feature under review stays untested, and the reviewer's attention is spent on files that have nothing to do with the change. Tests for components unrelated to analytics are explicitly out of scope.

§11 AC-9.1PR #31 files — 12 non-analytics tests
blog/BlogContent.test.jsx
T3-10Admin Dashboard rewritten — spec says out of scope

The PR rewrites Dashboard.jsx, adds a StatCard component and edits adminController.js. Nothing here is broken code — that is the point. Changes to the existing Dashboard page are listed as out of scope, so this is risk carried into a page nobody agreed to touch, in a diff already large enough to hide it. Scope is a review dimension, not a style preference.

§11admin/Dashboard.jsx
dashboard/StatCard.jsx
adminController.js
T3-11No page-level empty state

Analytics.jsx renders the filter bar, KPI cards, charts and tables unconditionally. A fresh blog with no posts gets a wall of zeros and blank axes — the reader cannot tell an empty database from a broken dashboard. The spec asks for 1 empty state with a call to action to create the first post. Again, nothing in the diff is wrong; the branch that should exist doesn't.

AC-8.2admin/Analytics.jsx:74

The tests that would have caught the bugs are the tests that were not written.

4 · Trusting the output · what the code actually does

Grounding gate: no real line, no finding

1 · The model returns JSON 
{ "file": "analyticsController.js",
  "start_line": 708, "end_line": 708,
  "severity": "critical",
  "title": "Bearer token logged" }
2 · Code checks, no LLM
  • Is the file in the diff?
  • Do lines 708–708 hit a changed hunk?
  • Secret leaks only need the file
3 · Only kept findings count
  • Score and merge gate come from kept findings
  • The model's own verdict is ignored
✓ kept · analyticsController.js:708 — line is in the diff
✗ dropped · auth.js:42–44 — “lines do not intersect any diff hunk”

Grounding is wider than the diff: a claim must point at something real

A line in the PR diffverified by code: this gate
A line in existing codeif it is in the context: callers, repo map
A line in the specif the spec is in the context

DevDigest's gate verifies only the first. Every dropped finding is logged with its reason. grounding.ts:52 ↗
